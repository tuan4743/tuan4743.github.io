feat(第三张): 新引擎开工 —— 纯 TS 定点模拟核心 + 按段落自动铺面

按定稿方案(GD 玩法骨架 + 本站科技风 + 自动铺面 + Phaser 4),这一轮先把【与引擎无关的地基】立起来。

新增 gd-web/(Hugo 不会碰它,构建产物以后放 static/assets/gd/):
- src/sim/constants.ts  物理常量表:全游戏唯一的"手感数字",每条都标了出处
  (GDOpenGD = OpenGD 源码常量 / 社区 = 社区长期口径 / 自定 = 我们自己定的)
- src/sim/level.ts      关卡模型 + 自动铺面生成器:全程用"块",不涉及时间
  —— 于是完全不需要采音(原作本身也没有严格采音标准);段落只声明"这一段长什么样",
  形态切换交给段首的圆环(和旧版定下的规则一致)
- src/sim/world.ts      定点模拟:60 帧驱动、内部 4 个子步(1/240),固定步长;
  方块/飞机两种形态,尖刺与方块侧面致死,平台/地面单向接住,坑掉落致死,
  圆环/速度门/重力门/存档点都要求"真的跨过去"才触发
- src/sim/replay.ts     回放:一卷输入 + 一套复活策略 = 一次跑动,可算状态指纹
- test/sim.test.ts      14 条验收(node --test,零依赖)
- tools/diag-bot.ts     排查机器人死在哪儿用的逐帧轨迹

验收:14/14 全绿,其中几条是关键证据:
- 常量表自检:一跳峰值 2.17 块、滞空 0.389 秒,解析值与模拟值一致
- 自动铺面:最小障碍间距 ≥ 一跳距离;每段都有对应形态的圆环与速度门
- 机器人 0 死亡跑完整关(1080 块)= "这一版铺面真的能过"
- 同一卷输入回放两次指纹完全一致;换输入/换关卡指纹就变
- src/sim 里不许出现 phaser / window / document(核心零依赖,可在 Node 里跑)

过程中修掉的真 bug(都是这份测试抓出来的):
1. 忘了实现"跳跃"输入 —— 方块根本跳不起来,机器人一路撞死;
2. 机器人的起跳判据按"外框前缘"算,导致早跳约 0.8 块、落地正好压在尖刺上
   → 改成按内框(7.5×7.5)算"能前进的距离";
3. 圆环原来放在本段内容之后,方块会一头撞进飞机走廊(必死关)→ 圆环提前到段首 +2;
4. 障碍最小间距 4.6 块只比一跳距离(4.49)多一点点,落地就撞下一个 → 提到 6.2 块。
