# WATER(CD3 铺面)导入:格式与映射草案

用户把 `CCLocalLevels.dat` 放在 `static/levels/`,里面两关:`WATER 2`(2334 物件,中间存档,忽略)
和 **`WATER`(8980 物件,x −9 ~ 3603.5 格,y −0.5 ~ 120.5 格)** —— 后者才是要用的半成品
(铺面写完、没加触发器特效)。

## 1. 格式(已实测跑通)

```
文件 = 每个字节 XOR 0x0B → base64 文本 → gzip → plist(XML)
plist 用的是 GD 自己的紧凑标签:<k>键</k> <d>字典</d> <s>串</s> <i>整数</i> <t/> <f/>
每关一份 dict,其中 k2 = 关卡名, k4 = 关卡数据
关卡数据 = base64(gzip("头部k,v,k,v…;物件;物件…"))
物件 = "1,id,2,x,3,y,4,flipY,5,flipX,6,rot,155,layer,21,color,…"
```
坑(都踩过):开头 `<?xml …?>` 会让自写的标签解析器卡死;字典循环必须带 `pos < 长度` 的条件,
否则读到末尾会空转跑不完。工具:`gd-web/tools/dat-report.ts`
(用 `--json=` 还能导出 JSON 摘要,便于脚本读)。

## 4. 导入要做的事(下一步)

1. **`gd-web/tools/dat-to-chart.ts`**:`.dat` → 我们的铺面 JSON
   (`{song, offset, segments:[{from,obstacles:[…]}]}` 或直接物件数组)。
   先把每个物件按 `x/30, y/30` 换算,再按映射表转成我们的 kind。
2. **映射表**(新文件 `gd-web/src/sim/gdids.ts`):`GD_ID → {kind, w, h, flip, …}`。
   现在 `gdmap.ts` 里只有 1/8/39/103 四条(刻意保守),这批 ID 正好把它补实:
   8 → spike、39 → spike(h=0.5)、468/469/83 → block、67/36/12/141/10/1022 → pad/orb(待确认)、
   1704/1751/2063 → portal(待确认)、3810/3812/3823/3638 → 需要新 kind 或忽略。
3. **要跟用户确认的**(他做的关,一句话就能定):
   - `83`(3779 个)到底是**方块**还是水/背景贴片?
   - `3638`(1167 个,带 `24`+`57`)是什么?
   - `67` / `36` / `12` / `141` / `10` / `1022` 里哪些是**跳板**、哪些是**跳环**?
   - `1704` / `1751` / `2063` 是不是传送门/形态门?
   - `3810/3812/3823` 是不是**锯片/齿轮**这类旋转危险物?
4. 我们没有的东西(先忽略并计数,别静默丢):物件级旋转(2158 个!)、
   装饰贴片、以及他还没加的触发器/特效。
5. 关卡长度 3603 格、最高 120 格 —— 我们现在 `ROWS=10` 的世界高度够不够要单独确认
   (游戏是固定视口 36 块宽、10 行高,120 格高的内容需要**纵向跟随镜头**)。

## 7. 出生点(用户指出的坑)

铺面第一段在**上一层**:y=0 那一层是空的,最底下的砖在 y≈5~16。开局把人放在 (0,0) 会
"从关卡底下往前跑",被压死 —— 这就是"bot 一直来回死"的根因。

原版靠**起点标记(物件 31)**定出生点。这关的 31 在 `x=0.5, y=10.5`(锚点是中心 → 左边缘 0、
脚底 10 格),所以:**出生点 = (0, 10)**,人站在第一段铺面的顶面上。
实现:`dat-to-chart.ts` 把 31 提出来写进 `Level.start`,`World` 构造时用它;存档点也记
"人越过它时的高度"(`checkY`),不然在 y=300 的存档点复活会摔到 y=0。

**相机/物体尺寸相关的两个"画布"坑(已修,记下来免得再犯)**:
1. Phaser 的 `ScaleManager`(mode: NONE)会把 `canvas` 的**行内样式**写成 `1280px×720px` ——
   画布于是固定 720 px 高,外框窗口装不下,多出来的被边框挡住(实测 38%)、露出来的那截是黑条,
   而且画面被纵向压扁 17%。→ 开局/resize 要把 canvas 的 CSS 尺寸按回 `100%×100%`,
   缓冲也要 `scale.resize(1280, 1280 × 盒高/盒宽)` 跟着盒子的长宽比走。
2. 游戏盒子 `.lost` 的 inset 走 CSS 的 `--sp-*`(FrameFit 写的窗口内缩量)就对了 ——
   **不要**改读 `--ff-win-*`(那是"中线包围盒",比窗口大一圈,会让画面超出窗口)。

## 10. 机器人(验收:这张图到底能不能过)

老机器人是"看见危险就跳"的反应式规则 —— 在真人设计的关卡上根本不够用:
它会在不该跳的隧道里起跳、撞死在天花板的刺上(实测死在 x=56 的 rot180 刺)。

新工具 `tools/autoplay.ts`:**向前试算**。每一小段(默认 3 帧)试几种"接下来怎么按"
(按住 1/2/3/4/5/6/8/10/13/16/20/26/34/44/60/90 帧,外加"什么都不按"),每种按法之后
交给兜底策略再跑 75 帧(兜底有"松手"和"反应式机器人"两种),活下来而且走得最远的那个就采用。
状态回退靠 `World.snapshot()/restore()`;为了跑得动,`World` 加了**窗口裁剪**(`w.windowed = true`,
每帧只遍历玩家附近 ±6~45 块的判定盒,实测从 4300 帧/秒提到 40 万+ 帧/秒)。

用法:`cd gd-web && node tools/autoplay.ts [--secs=600] [--step=3] [--horizon=75] [--tape=…]`
