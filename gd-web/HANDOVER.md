### 关于 SPWN

用户提过"甚至可以直接用 SPWN 语言编程生成铺面"。**SPWN 是把关卡编译成 GD 的 `.gmd` 格式的编译器**,
我们的引擎读的是自己的 `Level` 结构,没法直接吃 `.gmd`。所以这一轮做的是**借它的模型**:
铺面写成"按 onset/节拍的事件 + 图案库"(`level.ts` 里的 `patSpike / patSpikeOrb / patPitOrb / patPadRun`),
而不是"每 6 块一个随机障碍"。真要用 SPWN,可行的路子是"离线编译成一段显式物件列表(JSON)→ 引擎读 JSON",
但那样就没有"自动生成"了,得先决定要不要放弃自动生成。

## 1. 这是什么

第三张盘是一个**复刻几何冲刺玩法的网页关卡**:

- **玩法**:跑、跳(长按连跳)、形态(方块 / 飞机)、尖刺与方块致死、平台单向接住、坑、**弹簧**、**空中跳环**、
  圆环切形态、速度门、重力门、存档点、终点进度;
- **视觉**:本站的显示器 + holo 科技风,**不使用任何 RobTop 美术**(那是版权物);
- **关卡**:按**采音 onset 自动铺面**(`data/lost-beats.json` → `src/sim/beats.ts`),全曲 156.76 秒 / 1686 块;
- **时间**:画面由**音乐时间驱动**(`audio.currentTime` → 该推进到第几帧),所以障碍真的踩在鼓点上;
  复活时音乐 seek 到存档点对应的时间,后面每一拍仍然对得上。

参考:[OpenGD](https://github.com/Open-GD/OpenGD)(关卡格式)、
[camila314/gdp](https://github.com/camila314/gdp)(物理函数反编译)、
[GD 2.2081 的在线反编译](https://gd-src.undefined0.dev/)(本轮常量的出处,整理在 `docs/gd-physics-triggers.md`)。

旧的自研实现归档在 **tag `lost-from-scratch`**(含旧版 `draft()` 铺面算法与采音模块 `gd-beat.js`)。

## 3. 架构上的三条硬规矩(别破坏)

1. **`src/sim/` 里不许出现 `phaser` / `window` / `document`** —— 有测试扫源码盯着。
2. **自动生成的关卡必须"机器人 0 死亡可通关"** —— 任何铺面改动**先跑 `node tools/diag-bot.ts`**。
   这一轮它抓出 6 个必死图案,每一个都写进了代码注释(见下)。
3. **改物理常量 = 改铺面**:所有图案几何都是从常量推出来的(`level.ts` 的 `heightAt/arcOf/jumpLead`),
   常量一动,`diag-bot` 与 20 条测试必须重跑。

## 4. 这一轮踩过的坑(都留在注释里了)

1. **落点被"惯性跳"吃掉**:玩家按住不放 = 落地自动连跳。如果下一个障碍正好落在那一跳的落点上 → 必死。
   → `safeEnd()`:下一个"要出手"的障碍,右边缘必须超出"落地后一跳够得到"的距离。
2. **弹簧被提前起跳躲过**:机器人在离弹簧 2 块时看见弹簧弧线里的刺,提前起跳、从弹簧头顶飞过去。
   → ① 弹簧连**第一个弧线里什么都不放**;② 弹簧间距**不许超过一跳的跨距**(中间不留"在地上跑"的空档);
   ③ 弹簧连还要一段**干净的助跑道**(前面有刺就得先把这一段的 onset 让开)。
3. **弹簧"临界距离"算错**:扫"脚底低于 0.625 块"时从 d=0.02 开始,第一次就成立 → 临界值算成 0.02,
   弹簧间距直接乱掉(实测 5.25 块的间距让玩家从弹簧头顶飞过)。要取**下落时穿过** 0.625 块的那一处。
4. **触发点比物件左缘早 0.625 块**:内框右缘先碰到它。所有弧线几何都要按这个偏移算,否则差半块、当场撞死。
5. **机器人会为"已经过去的刺"起跳**:按外框判"过去了"太晚 → 落地瞬间被动起跳。
   → 按内框判:`o.x1 <= w.x + P.innerOff`。
6. **弧线下面放方块 = 断链**:方块把地面抬高 1 块,玩家落在方块顶上之后够不到下一根弹簧。
   → 弹簧弧线下面**只放尖刺**。

### 13.2 两个真 bug(都不是"猜错了常数",是实打实的实现错)

1. **线框判定盒**(`src/sim/gdids.ts`):`hitboxOf` 对所有 `kind:'frame'` 一律返回 30×30,
   于是**细杆变成了整格的隐形墙**。原表 `.tmp/longdata.cpp:23` 给的是 468/475 → `{1.5, 30}`、
   469/470/471 → `{30,30}`、661 → `{15,15}`、662/663 → `{15,30}`,而 `GameObject.cpp:766-772`
   是"表里的盒子 × 物件自己的缩放" ⇒ **判定就是物件包围盒**。修法:`case 'frame': return null`。
   ★ 1×1 的 L/U 形仍是整格(用户当初那句"一格宽的线框变成小于一格"说的就是这类,行为不变)。
2. **`tapeOf` 丢了链根那段按键**(`tools/autoplay.ts`):出生点是根时它的 inputs 本来是空的,
   看不出问题;`--seed` 热启动时根在关卡中间,于是**存下来的卷子自己回放不出来**
   (文件写着 x=512.9,回放 182 帧就死),而且错误会一路滚进下一站。现在存盘前先自检:
   拼出来的卷子必须能从出生点原样回放到那个 x,否则拒写;并且只准变好(不许覆盖更好的冠军卷)。

顺带补的物理:机器人重力 **0.9 档**(`gdp master PlayerObject_updateJump.cpp:309-315` 的 `float_b`)。

### 13.3 搜索这一侧治好的三个"钉死在一处"

1. **分数没有纵向梯度**:贴天花板的路 x 走得最远、分数永远第一,可它降不到门口 ——
   7 万节点 + 6 次重启都卡在 x=421。加了"朝门口的梯度"(进门口 60 块内,按玩家盒子到门盒子的
   纵向距离扣分:超 2 块容差、3 倍权重)之后,一次推过 x=421/512 两个卡口。
2. **"最远活着"按 x 选是错的**:球形态段有个"翻着重力的球一路飞到 y=117"的节点,x 最远

   怎么搜都过不去(实测卡了 6 站)。现在按**分数**选,写出去的前缀一定"既远、又走在正路上"。

### 13.3b 第二波(把铺面路线从 485 推到 524)

四个坑,全在搜索工具里,不在物理里:

1. **约束的作用域错了**:`--noskip` 原来写在【每帧推进】里,于是"跳过了门"的**试算**当场被判死 ——
   试算本来就是在探路,判死它等于把宏动作和长视界一起掐掉(实测 x=481 起搜:关约束 497.7,
   开约束只剩 481.4、50 个节点耗干前沿)。现在试算自由跑,只在"这个状态要不要留下"时判一次
   (`constraintOk()`);留下了却跳过门的,下一帧照样判死,约束一点没松。
2. **同分要取更远的**:分数在一段路上是平台期,只认 `>` 会让最佳节点永远停在平台期第一个节点上
   ("明明走到 484.8,报出来 481.4")。现在同分取 x 更大的。
3. **进度和卷子分开记**:`maxX`(活着走到的最远)只要更远就记;`tape` 只在分数变好时才换。
   以前只有一个"x 不许变小"的闸门,一次"走到 523.6 但卷子在 488.0"的尝试会被上一局的 488.3 挡掉,
   进度推进了 11 块却什么都没记,分站搜据此判"没过"并放弃整条路线。
4. **`--startfrom=<卷子>,<块>`**:沿着卷子走到第 N 块,【用那个真实状态】当搜索根并清空前沿。
   卡住的原因常常不是"那一段过不去",而是"前缀末端是个死状态"(站 14 的前缀末端是个在空中
   翻着重力的球)。实测同一段:带包袱搜 70 秒过不去,`--startfrom` 3.4 秒过。
   分站驱动的重试顺序:接着搜 → 退回 45/30/15 块重开前沿 → 剪尾 20 块;
   离目标 ≤6 块时自动给双倍时间(站 18 就差 1.8 块)。

调试旋钮:`--trace=N`(前 N 次展开的候选情况,还会打出每个候选"为什么没留下":
边内死 / 过顶 / 跳过门)、`--startspeed=N`(定点实验指定速度档)。
定点实验的副产品:卡口那一段在**速度档 0(最慢)**下才真难(483 就过不去),速度 1/2 都能过 ——

  搜索没有"往下贴"的动力 —— 这是本轮唯一改默认值的搜索参数。
- `--sawbase=1`:锯片判定盒改用【不缩放的基础尺寸】(中心对齐)。本关 552 个锯片,

  且偏移正好是 −w/2 / −h/2(中心对齐)✓ 与我们的表一致;但"原版会不会把判定盒一起乘缩放"
  没有直接证据(我们目前是乘的)。A/B 结果:**开关不影响 x=1060 这个卡点**
  (两边上限都是 1061.0),所以本关暂时维持"跟着缩放走",开关留给以后有反例时再用。

**★ 根因(这一轮最后查到的,是真 bug,不是"搜索不够聪明")**:`portalSatisfied` 对
【放大门】的判据写反了 —— 原来一句 `sizeMul !== 1`,对迷你门是对的,对放大门恰好相反:

- 而这一段是照**普通大小**设计的:手工把状态摆成普通方块、出门 y=24.05~24.2 / vy=-0.32

**顺带修的驱动排序**:判据修好后,"前十块就跳了门"的短卷子在"跳门少"这一条上会赢过

### 13.16 x=1060 robot 门:过门的**机制**找到了(按住 = 反重力下往平台里压)

★ 关键实测(单点、可复现):反重力方块在平台上方 0.4 块处,
- **按住** → `diag-run 1058 22.4 cube ... hold -1 2 5 -0.1`:y 从 22.08 → 21.87 → 21.79 → 21.71
  → 22.00(贴地)→ 21.92,**一路被平台托着走**,robot 门在第 5 帧就生效了 ✓;
- **松手** → 同一起点:idle 时 22.33 → 22.95 → 24.15 → 25.93 → 29.95,**直接飞走** ✗。
所以过门的形状是"**下扎到平台面附近 + 落地瞬间按住**"(反重力下按住 = 朝重力反方向蹬,
正好把人压回平台),不是"贴着天花板飞过去"。

**这条走廊的硬约束**(全部来自判定盒,已核过表):
| 物件 | 盒子 | 对玩家的要求 |
|---|---|---|
| 锯片 1052.385(scale 1.5) | x≤1054.61, y≤23.65 | 盒子还压着它时 y 必须 > 23.65 |
| 速度门 1055 | x≤1056.35, y[24.57,26.43] | 压着它时 y > 23.57(必须吃到它,否则算跳门) |
| 平台 1056~1066 | 顶面 y=22 | 想被托住就得下到 ~22 |
| robot 门 1060 | x[1059.93,1061.07], y[22.07,24.93] | 这一段 y 落在 (21.07, 24.93) |

即:1054.61 之前不能低于 23.65,1056.35 之前不能低于 23.57,然后要在 1059.93 之前下到 ~22.5
并按住 —— 一条"先压住高度、再下扎、落地按住"的波浪动作。

**这一轮为此写的三个定点工具**(都在 `tools/`):
- `probe-gap.ts`:定点缝隙搜索 —— 去重键**不带 tick**、目标就是"某个门生效"、束宽可给到 2 万。
  和 autoplay 的区别很实在:autoplay 的状态去重带 tick(同姿态不同帧不算重复),束会被等价状态灌满,
  而且它的目标是"走得越远越好",在这种地方正好是反的。
- `hand-dive.ts` / `hand-sweep.ts`:手工/枚举尾段(先松 D 帧再交替按住、或 `--pat=0011...`),
  报"门生效 + 跳过几个门",合法就写 `gap-tail.json`。
- `tape-splice.ts`:把尾段拼回前缀并**回放自检**(顺带数生效/跳过的门)。
- `hand-trace.ts`:逐帧打印,查"为什么没进门"。

⚠ **工具自己有 bug,先记下来免得下次再踩**(都修了):
1. 门的 Box 必须从**正在用的那个 World** 里取 —— 每个 World 各建一套 Box 实例,
   拿 A 的 Box 去 B 的 `armedPortals.has()` 永远 false。这个 bug 让 probe-gap/hand-dive
   一度"证明"了三个门都无解,其中一个是路线本来就会过的 cube 门 —— 自检当场穿帮。
2. gate 违规必须**整条作废**,不能只 break 内层循环(第一版违规状态照样进束)。
3. 回放到起点时必须**每帧记账**(`gateOk`/审计),否则"当时满足、过后不满足"的冗余门
   会被误判成跳过(实测:起点处误报"跳过 19 个门")。

**当前状态**:legit 前缀 **1061.0/3620(29.3%)· 生效 41/108 · 跳过 0**;驱动在这一站
把重试清单跑完(38 次)后停下,等下一轮换思路。

### 13.9 蓝色重力跳点要认【朝向】(2026-09 这一轮,物理)

出处 gdp@2.11 `checkCollisions.cpp` 的 kBlueBump 分支:

### 13.10 落块吸附(方块连台阶时的 ±1~2 单位横向修正)+ 一个"裁剪改物理"的隐患

**落块吸附**(出处 gdp master `PlayerObject_checkSnapJumpToObject.cpp`):原版每落到新方块上,
看它和上次落的那块差多少 —— littleStair / downStair / bigStair 三档(按 `m_playerSpeed` 与体积查表),
正好差这一档就把人的 x 拉回"和上次落点相同的相对位置",最多挪 1~2 单位(`threshold`)。
只有方块形态调它(`if (vType == Cube) …`)。已实现:`snapObj`/`snapDist` 两个字段进了 `WorldSnap`,
搜索回退和回放都跟着走;新增单元测试(标准台阶 vs 对照)覆盖 → `sim.test 39/39`。

★ **隐患**:加上它之后存盘自检立刻报警 —— 搜索(开窗口裁剪)拼出来的输入卷,用完整物理回放只走到
270.1 块,节点状态却在 316.7 块。两个 World 回放同一卷完全一致 ⇒ 不是不确定性,而是**同一高度上
有多块方块时"算落在谁身上"取决于遍历顺序**,裁剪后的 `nearSolids` 顺序与完整列表不同。吸附之前
只用到了高度 y,这个选择无所谓;加了吸附它直接决定 `snapObj`,两种模式就此分岔。
**改法:同高时一律取最靠左的那块(`b.x0` 最小)** —— 与列表顺序无关,verify-run 的
"窗口裁剪指纹一致"照旧成立。教训:**任何"落点记忆 / 对象身份"类的新状态,都要检查它是不是
依赖列表顺序**,否则裁剪模式与完整模式会悄悄分家。

### 13.12 站 18 的死因查清了:**球态走廊出关时的"重力奇偶"**

铺面路线在 cube 门(525)前反复卡住(几十次"没过")。逐层挖出来:

1. 种子回放的判据漏了"冗余门不算跳过" → 每次热启动都在 493 块被截断(已修,见提交 `f5ebba6`);
2. 从种子末端【什么都不按】往前跑:球贴地滚到 525.69 ✓ 穿过一格走廊 ✓,过了 cube 门之后
   **一路飞到 y=49** —— 因为球态走廊里"点一下翻重力"把重力留在了【向上】,一变回方块就朝天上掉;
3. 合成对照实验(同一位置、同一速度档、同一形态):

   | 起步重力 | 走到 |
   |---|---|
   | **向下(正常)** | **559.5 块** ✓ 过 cube 门 |
   | 向上(反重力) | 507.6 块 ✗ |

   ⇒ **这截走廊只允许"正重力"出关**。球每次点按翻一次重力,所以出关时的重力 = 起步重力 ×
   (−1)^点击数 —— 这是个【全局奇偶约束】,现在的启发(朝门口对齐 + 局部天花板)看不见它:
   天花板只在"要不要留下状态"时判,于是那些"进门后朝天上掉"的子状态被拒掉、前沿直接枯死(日志里"宏 0")。
