## 0. ★ 最新用户反馈(优先级最高,先做这个)

用户实测反馈(2025 收口后的第一轮真实试玩),逐条 + 我的判断:

| # | 用户说 | 我的诊断 | 怎么修 |
|---|---|---|---|
| 1 | **帧率完全没问题,稳定 60 帧** | ✅ 里程碑最后一条(真机 60fps)达成 | 无需处理 |
| 2 | **画面特别大,整体缩小一倍** | 相机 zoom = 720/(10×30) = 2.4 → 可见约 17.8 块宽;用户旧版习惯约 31 块 | `main.ts` 里 zoom 改成 `720/(ROWS*U) * 0.5`(或抽成常量 `VIEW_BLOCKS` = 36 块宽);同时把玩家落点比例 0.22 保留 |
| 3 | **重力方向是向上的,整个游戏都是反的** | **这是渲染层的 bug,不是物理**:世界坐标 y 向上,而 Phaser 相机是 y 向下 → 我的 `draw()` 直接把世界 y 当屏幕 y 用,于是整幅画面上下翻转(玩家下落看着像上升、尖刺朝下)。模拟核心是对的(Node 14 条用例里"落体/跳跃/落台面"全绿) | 在 `draw()` 里引入 `const Y = (wy:number) => ROWS*U - wy;`,把所有 y 统一过一遍:物件的 `by` 变成 `Y(o.r*U + o.h*U)`、三角顶点、玩家中心、判定内框、终点线、死亡遮罩。**改完必须重跑 `gd-panel-check` 并看图确认尖刺朝上、地面在底部** |
| 4 | **铺面完全没有原版那种感觉**;建议**改成全采或采大部分** | 现在生成器只用"固定间距 + 随机 roll",和音乐/节拍无关 —— 所以看着不像 GD。用户的旧版有采音(`gd-beat.js`,已归档在 tag 里),GD 官方铺面本质上是**跟着节拍放障碍** | 把生成器改成**基于 onset/节拍**:用 `static/assets/cd/*.json` 或重新采音得到的 beats 列表,按 1/4、1/2、1 拍为格点放障碍(全采 = 每个 onset 都放,采大部分 = 每 2 个取 1);GD 1.0 的典型形态:地面尖刺带、方块阶梯、平台跳、尖刺+方块组合。**注意:间距仍必须 ≥ 一跳 4.49 块,机器人闸门不许破** |
| 5 | **有些意义不明的平台,踩都踩不上去** | 生成器里"高空平台"(row 2~5 随机)确实是够不到的装饰 | 删掉随机高空平台;平台只放在**跳得到的高度**(row 1~2,且前面有落脚点),或者干脆用方块阶梯代替 |
| 6 | **美术不直观**(尤其"坑"画成半圆形)、整体粗糙 | "半圆"其实是坑口的**警示光**(`deco light` 画成实心圆)。坑本身只是地板断开,看不出是坑 | ① 坑:地面断口画成**明确的深色缺口** + 两个断崖边(锯齿/剖面),警示光改成向下的小三角或直接去掉;② 尖刺、方块、平台、圆环、速度门各给一个"一眼认得出"的形(参考 GD 的轮廓而不是色块);③ 段落色的用法再收敛一点 |
| 7 | **实现逻辑没有还原,实在不行照用源码** | 移植 OpenGD 源码已评估过不可行(它自述 UNMAINTAINED、关卡不可玩、`proj.wasm` 是模板样板、跑起来要自备 RobTop 版权资源)。但"按反编译的常量还原手感"是能做的 | 用**已核实的 OpenGD 常量**替换掉我早期用的社区近似值:速度门 `(5.98,0.7)/(5.77,0.9)/(5.87,1.1)/(6.0,1.3)/第5档`、飞机加速 `0.8/-1.0/1.2 + 长按 0.4~0.5 帧后额外推力`、UFO 冲量 7(迷你 8)、球重力 ×0.6、机器人 `newYVel*=0.9`、终端 ±15;再加 GD 的**方块空中自转 90°/次**、跳跃缓冲等手感细节 |

建议顺序:**3(反的)→ 2(缩小)→ 5(删掉够不到的平台)→ 4(按节拍重做铺面)→ 6(美术)→ 7(常量与手感还原)**。
第 3 条是"一眼就坏"的,先修它;第 4 条工作量最大,但它决定"像不像 GD"。

## 1. 这是什么

第三张盘从"从零手搓的几何冲刺小游戏"改成了**新引擎**:

- **玩法**:复刻几何冲刺的骨架 —— 跑、跳(长按连跳)、形态(方块 / 飞机)、尖刺与方块侧面致死、
  平台与地面单向接住、坑掉落致死、圆环切形态、速度门、重力门、存档点、终点进度;
- **视觉**:本站的显示器 + holo 科技风,**不使用任何 RobTop 美术**(那是版权物);
- **关卡**:按段落与形态**自动铺面**生成(下一步要改成按节拍生成,见第 0 节第 4 条);
- **参考**:[OpenGD](https://github.com/Open-GD/OpenGD)(关卡格式与数据结构)、
  [camila314/gdp](https://github.com/camila314/gdp)(GD 物理函数反编译)。

旧的自研实现在 **tag `lost-from-scratch`** 里归档(含那份 `draft()` 自动铺面算法,以及采音模块 `gd-beat.js`)。

## 2. 代码在哪、怎么跑

```
tuagfey-blog/gd-web/            ← 引擎源码(独立 npm 工程,Hugo 不碰它)
  src/sim/constants.ts          ← 物理常量表(全游戏唯一的"手感数字",每条标了出处)
  src/sim/level.ts              ← 关卡模型 + 自动铺面生成器
  src/sim/world.ts              ← 定点模拟 + 机器人(botThink)
  src/sim/replay.ts             ← 回放 + 状态指纹
  src/main.ts                   ← Phaser 4 场景:固定步长驱动 sim、相机、科技风绘制、音乐、HUD
  src/embed.ts                  ← 页面入口:找 #gd-canvas 启动;手机端不启动
  test/sim.test.ts              ← 14 条 Node 验收
  tools/diag-bot.ts             ← 排查"机器人在哪儿死的"逐帧轨迹
  vite.config.ts / vite.lib.config.ts  ← 预览页构建 / 博客单文件构建

命令(都在 gd-web/ 下):
  node --test test/sim.test.ts   # 模拟核心验收(14 条,零依赖)
  npm run build:embed            # 构建给博客的 gd.js(约 387 KB gzip)
  node tools/diag-bot.ts         # 机器人死亡轨迹
```

验收脚本在 `tools/verify/`:`gd-web-check.mjs`(预览页)、`gd-panel-check.mjs`(真实页面+显示器框)、
`live-lost2.mjs`(站点整体)。

## 3. 架构上的两条硬规矩(别破坏)

1. **`src/sim/` 里不许出现 `phaser` / `window` / `document`** —— 有测试扫源码盯着。
2. **自动生成的关卡必须"机器人 0 死亡可通关"** —— 任何铺面改动**先跑机器人**,过不去不许提交
   (第 9、11 轮各回退过一次,都是这条规矩救的)。
