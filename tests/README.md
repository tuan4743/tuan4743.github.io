## 外壳与平移过场(第五轮,第一批)

用户的整体想法:**世界坐标从左到右依次是【CD 选择页 | 首页(仿真屏幕)| 其他页】** ——
其他页住在首页的**右边**,是另一张页面、不是同一页里的东西;
点平板上的 APP 时,整块机器**向左平移 100vw**(视口往右移)出去,滑完再跳过去。
为了不穿帮,**滑走时露出来的背景必须和落地页是同一个样式**,
于是看起来像"在同一个页面里平移"。

> ★ 方向别再做反:是"去右边那页"⇒ **内容向左滑**。
> CD 架那套是反过来的(架子在左边 ⇒ 内容向右滑 66vw 把它拉进画面)。
> 两套共用的是 `.scene` 上的 `transform` + 同一条缓动曲线,方向各写各的。

第一批交三样:**宇宙背景 / 三角投影 / 向左平移过场**(`shell-slide.test.mjs` 钉这三样)。

### 三条"必须一致"的约定

| 东西 | 约定 | 为什么 |
|---|---|---|
| 宇宙背景 | `.cosmos-nebula` / `.cosmos-grid` **只有一份声明**(`assets/css/extended/shell.css`),CD 架的标记也挂这两个类 | 两处各写一份迟早会漂;用户要的正是"两处一个样式" |
| 投影 | 等腰直角三角形。**首页那一份是机器的一份子**:`.scene` 的子元素、贴屏幕右缘外侧(`left: 100vw`),被机器的 `translateX(-100vw)` 带着扫进来 —— 静止时在视口外所以看不见,滑完正好停在左上角。**博客页那一份**就在左上角(`left: 0`)、一直可见、`z-index: -1` 压在内容下面 | 用户原话:"我要的是贴着屏幕,跟着屏幕移动"。它自己**没有任何动画** —— 上一版做成"淡入"被否掉了:"动画没播放完这个东西直接就跑到屏幕上了" |
| 三条 transform | `.scene` / `.tablet` / `.statusbar-toggle` 的时长**必须是同一个数** | 平板和顶缘按钮不在 `.scene` 里(层级原因),漏一个就是"屏幕滑走了、平板还在那儿" |

### ★★ "底层背景不变"≠"内容背景不变"(这里曲解过一次)

用户的完整意思是:

- **底层背景**(那片星云)**不跟深浅主题走** —— 所以 `body` 要透明,
  让 `.page-cosmos` 露出来,`.page-cosmos` 自己是 `z-index: -1`;
- **内容自己的背景**(正文那张卡片)**按主题正常变化** —— 深色主题下深卡、
  浅色主题下浅卡,字色也跟着走。

第一版把 `--primary` / `--content` / `--entry` / `--border` 整套都改成了"深底浅字",
等于**把主题整个按死** —— 那不是用户要的。现在只动"页面底色"这一件事,
卡片用 `color-mix(in srgb, var(--theme) 86%, transparent)`(主题自己的变量)
调出来,所以深浅一切换它自己就跟着变。测试里钉了两条:
**不许覆盖主题调色板** + **面板必须用 `var(--theme)` 调**。

### ★★ "平时看不见"要问清楚是【哪一种看不见】

投影这个元素来回改了四版,每一版都是"看不见"的实现方式不对 —— 值得记下来:

| 版本 | 做法 | 用户看到的 |
|---|---|---|
| ① | 钉在视口右上角的小节点 | 位置不对 |
| ② | 钉在视口左上角 | "CD 页和内容页都会出现";而且**它不跟着屏幕动** |
| ③ | 钉在视口左上角、靠 `opacity` 门只在过场亮 | **"你为啥要设置成可见性啊…动画没播放完这个东西直接就跑到屏幕上了"** |
| ④ | 放进 `.scene`、贴屏幕右缘外侧(`left: 100vw`),跟着机器平移 | ✓ |

★ 关键区别在**它属于谁**:
- ②③ 把它当成"钉在视口上的一个特效",于是要么哪一页都看得见,要么自己排一条时间线;
- ④ 把它当成**机器的一部分**:机器在动,它被机器带着走 ——
  静止时它正好在视口右边之外(所以看不见),机器左移 100vw 时它从右边扫进来,
  最后停在**视口左上角**,正好和博客页上那一份对齐。

★ 由此得到一条**可以算的不变量**(测试里就是算出来的,不是"看着像"):

```
平移量(-100vw) + 首页起始位置(100vw) = 落地位置(0vw) = 博客页那一份的位置
```

★ 顺带:博客页那一份要 `z-index: -1`(定位元素的 `z-index: 0` 会画在静态正文之上,
而左上角正是 logo 的位置),顶栏也要做成半透明磨砂,否则那条不透明的顶栏
会把三角形上面一截切掉。

### ★★ 背景必须"钉在视口的最底层"——这里踩过一个坑

第一版写完之后用户报:**"你把它固定在了滑动界面内,不仅挡住了主页面,
滚轮一滚还跟着走。"**

根因有两层,两层都得治:

1. **它其实没被 fixed。** 这份标记是在 `<footer>` 里渲染出来的(主题的
   `_partials/footer.html` 调 `extend_footer.html`),而 `cosmos.html` 那层
   `.cosmos` 是 `position: **absolute**` —— 直接放进去,包含块就变成
   "文档初始包含块":变成一张钉在**文档顶部**的图,页面一滚它就跟着走。
   ⇒ 外面必须套一层 `.page-cosmos`(`position: fixed; inset: 0`)。
2. **就算 fixed,`z-index: 0` 也会盖住正文。** 同一个层叠上下文里,
   定位元素(哪怕 `z-index: 0`)排在**静态块级内容之后** —— 而正文
   `<main class="main">` 正是静态的。
   ⇒ `.page-cosmos` 用 **`z-index: -1`**(画在内容之前、html 底色之后),
   同时页面底色交给 `html.shell-page`、`body` 设成 `transparent`
   (否则 body 自己的背景会把负 z-index 那层盖掉)。

★ 教训:**"看不见的层"要同时说清"相对谁定位、画在第几层"** ——
只写 `position: fixed` 不写 z-index,或者只写 `inset: 0` 不写包含块,
都会在别的页面结构下变成另一个东西。

### CSS 走 PaperMod 的 extended 通道

`assets/css/extended/*.css` 会被主题的 `head.html` 自动拼进全站样式表 ——
首页(独立模板)和其余页面都吃得到,不用各处注册。
**代价**:这份样式表在 `intro.css` **之前**加载,同分时后加载的赢,
所以右滑那几条的选择器写成 `body.intro-page.page-out .scene`(三个类),
专门压过 `intro.css` 里的 `body.scene-open .scene`。

### 两个探针坑(都在这一轮踩的)

1. **最小化产物里属性没有引号**:`/class="intro-bg"/` 一个都匹配不到 ——
   这已经是第三次了,现在统一用 `class="?intro-bg` 。
2. **读时长要把前导点带上**:`.55s` 用 `[\d.]+` 抓到的是 `"55"`(= 55 秒),
   于是"三条时长一致"那条断言把 0.55 和 55 判成不一致 ——
   和之前 `.36s` 被读成 36 是同一个坑。现在是读出来 **parseFloat 比数值**,
   不是数字符串出现几次。

### 这一批**没有**做的(第二批)

- 落地页本身的版式(博客页要"轻量、舒适")—— 现在只给了同一片星云、
  一层磨砂内容面板和浅色字(浅色字是**故意**的:背景恒定不跟主题走,
  字就得跟着背景走,否则浅色主题下会变成深灰字压在黑星云上)。
- **回来的方向**(从博客页滑回首页):那些页面还没有 APP 列表,等第二批。
- 那些页面上仍然留着旧顶栏(给它加了 `padding-right`,别压到左上角那面三角投影上)。

## 首页:平板主界面(2026-09-27 那一轮)

- **`tablet-home.test.mjs`(39)** —— 按下屏幕顶缘那枚下拉按钮,整块屏幕变成一页
  "平板主屏"(导航变 APP、搜索一张卡片、时钟/最近更新/标签几张卡片)。
  验的是**结构 + 层级 + 几何**三件事,其中几何那几条最值钱。

### ★★ 断言不能钉"我当时那么写的",要钉"能推导的事实"

第一版里有一条断言叫"平板层和黑屏层【用同一套定位变量】",它把
`inset: var(--sp-t) var(--sp-x) var(--sp-b)` 当成对的钉住了。可那组变量
**只定义在 `.screen` 上**,而平板挂在 `<body>` 下、`.screen` 外 ——
取不到就等于整条 `inset` 作废。断言钉的是一个**本来就不成立的东西**:
它一直是绿的,而页面是错的。

同一个坑在用户这一轮反馈里爆了三条(他说的是"大小不对,不能贴到屏幕的框"、
"搜索栏太大,顶出去了"、"有些卡片貌似没生效"):平板靠 `frame-fitted` 的
`inset:0` 兜底 + `clip-path` 裁出玻璃形状,于是**内边距从视口边缘算起**,
而玻璃是往里缩了一块(左右 5vw、上下 13vh/7.5vh)—— 内容被裁掉上面一条、
左边一条:日期+电量整行没了、时钟只剩半截、搜索卡片左半截和放大镜图标
落在玻璃外。

现在那条断言换成了**算出来的**结论:把 CSS 里的 `clamp()` / `var()` / `calc()`
按参考视口(1850×848)真解成 px,和玻璃四边比大小 ——

```
内容内边距 83/127/82  ≥  玻璃 68/93/67/95
```

把它改回 `padding: 12px 34px` 立刻变红(报 `12/34 ≥ 68/93/67/95`),能红才算数。

### ★★ 层级问题的根因是"层叠上下文",不是"数字不够大"

用户原话:"图层比下拉按钮要高,但是实际应该是下拉按钮的图层最高"。
那枚按钮当时写着 `z-index: 41`,平板是 `40` —— 数字上按钮更大,却被盖住了。
原因是 `.scene` 是 `position: fixed`,而**fixed 元素自己创建一个层叠上下文**:
`.screen` 里写的任何 `z-index`(包括 41)都被封在 `.scene` 这一层里,
对外一律算 0 级。平板在 `.scene` **外面**,40 就赢了。
(截图里那枚箭头只露出上半截,正好也是这个 —— 平板 `clip-path` 的上缘
压在它中间。)

所以修法是结构性的:把按钮**搬到 `.scene` 外面**,并把它的 `top` 从
`--sp-t`(那是 `.screen` 上的变量)换成 `--ff-win-top`(frame-fit.js 写在
`<html>` 上,body 这一层看得见)。断言也改成验**结构**:
在渲染产物上做标签配对,断言开关的偏移量落在 `.scene` 的 `[start, end]` 之外。

顺带:CD 架拉开时 `.scene` 会整体左移 66vw,而平板不在 `.scene` 里、
不会跟着走 —— 所以架一拉开就**显式把平板合上**(`MutationObserver` 盯 body 的
class,那边是 `classList.toggle`,没有事件可听),按钮也一起隐藏。

### 其它几条

- **记忆键要和别人分开**:`intro.js` 那套"显示/隐藏状态栏"用的是
  `cd-statusbar`,而且**每次进页面都会写一个 `"1"`**。平板第一版复用了同一个键,
  结果每次刷新平板都自己弹出来、还关不掉。现在平板用 `cd-tablet`。
- **磁吸光标的选择器要跟着加**:`magnetic-cursor.js` 的 `SELECTOR` 兜底那条是
  `button:not(.frost-shard)`,而 5 个 APP 都是 `<a>` —— 用户报"扫描框移上去
  不会吸附"就是这个(只有那枚 `<button>` 播放器会吸)。已加 `.tablet__app`。
- **`auto-fit` 网格会把少量元素摊开**:`repeat(auto-fit, minmax(88px, 1fr))`
  在 1850px 宽的屏上给 5 个图标每格 ~350px —— 看着就是"很空"。
  改用 flex + `justify-content: center`,图标按屏高 8% 固定大小。

### ★★ "必须盖住"和"留一圈余量"是两种轮廓,不能共用一份

用户第三轮的原话:"把五张CD的动画,内容页全做成我们这个页面的大小,
这样这个平板界面就能完全遮住了" —— 他看到的是一圈露出来的东西。

根因:平板当时用的是 `--ff-clip`,而那份轮廓是给**黑屏/花屏层**用的,
被 `frame-fit` 刻意 `shrink()` 往中心收过(k≈0.979),四周留了一圈余量。
平板在那一圈里什么都没有,底下那张 CD 页就露出来了 ——
1850×848 下量出来是 **左 7 / 上 8 / 右 18 / 下 7 px**。

修法:`frame-fit` 多算一份【覆盖轮廓】`--ff-clip-cover` = **未收缩**的逐行轮廓
+ 每行各自往外让 5 贴图像素(≈4 屏幕像素),**只给平板用**;
黑屏层仍然用收过的那份(它确实需要那圈余量)。

★ **两个走不通的做法(都试过,数值复算在 `.tmp/frame-gap.mjs`)**:

| 做法 | 结果 |
|---|---|
| 在收过的轮廓上加固定外扩 | 补不回来:`shrink` 在左右两边挖掉的是 ~20px(离中心越远挖得越多),还是露 13px |
| 整体放大一个倍数 | 倍数被最极端那一行(左侧电源键那道凹口,比别的行多探出 13px)决定,算出 1.028 —— 于是**所有**行一起被推出去 23px,平板会啃掉一整条左边框 |

★ **单位坑**:`medL/medR` 是缩略图坐标(要 ×S),而 `pts` 里的 x/y 已经是贴图坐标 ——
混用会把"窗口中心"算错,算出 kc=1.69,平板整个糊到边框外面去。
第一版就是这么错的,而且是**探针(不是眼睛)抓到**的。

★ 为什么不去"把五张 CD 页缩小成平板那么大"(用户提的那个办法):
那样每张页面四周会露出一圈 `.screen` 的底色,变成"浮在框里的小方块" ——
**那是之前专门修掉过的回归**(见 frame-fit.js 里 `clampSp` 的注释)。
所以正确的做法是反过来:**让平板长大到盖住整块玻璃**,而不是让页面缩小平板。

### 展开的东西要长在它自己的卡片里

用户:"搜索栏卡片还是不太丝滑,原因是展开后不是在卡片内的"。
第一版把结果面板绝对定位挂在卡片**下面** —— 视觉上是两块,展开时还压住下面的卡片。
现在结果面板就在卡片里(`flex: 1 1 auto`),卡片高度由整行决定,
**展开不改任何布局 ⇒ 不会跳**。
入场用 `animation` 不用 `transition`:元素从 `display:none` 变可见的那一帧,
transition 没有"上一帧"可以插值,根本不会跑。

### 控制类的东西:连过去,不要抄一份

"明暗 / 音量"原来在顶栏,平板一开就被盖住(用户要它们回到时钟卡片右边)。
平板里**一行控制逻辑都没重写**:明暗 = 去点顶栏那枚 `#theme-toggle`,
音量 = 写进顶栏那条 `#volume-range` 再派发一个 `input`。
状态仍然只存在 `theme-palette.js` / `cd-audio.js` 那两个键里,
两处不会各存一份(这个项目里已经踩过一次"同一个 localStorage 键两套语义")。

★ **断言里要先剥注释再扫源码**:这段代码的注释里本来就写着 `pref-theme`
(解释为什么**不**去写它),不剥就用自己的说明把自己判红 —— 本轮又踩了一次,
和 README 里那条"注释会毒化源码扫描"是同一个坑。

删它本身只是一行(把 `<div class="statusbar">` + `partial "header.html"` 拿掉),

顶栏没了以后就没有"原件"可点,代理也就没有意义 —— 少一套状态、少一套要同步的样式。

### ★ 注释会毒化源码扫描(这一轮第三次)

### ★★ 第五张盘的五个坑

**① 交互:测试全绿,页面是死的。** 用户报"刮了也没反应",而当时 21 条断言全部通过。
`pointer-events` 会继承:`.frost-shards` / canvas / 标题全是 `none`,
整页只有 `.frost` 能被指针命中,而监听却挂在碎片层上。
测试绿是因为它**直接把事件塞给了模块挂载的那个元素**,绕过了"事件能不能到达"。

现在测试:从 `pages.css` **读出**每个元素真实的 `pointer-events`(改 CSS 会同步影响测试),
按浏览器的命中测试派发,并模拟 `setPointerCapture`。这里又有三个必须照做的细节:

```
· 元素默认值是【null(没声明)】,不是 auto —— pointer-events 是继承属性,
  默认 auto 会把继承链断掉(碎片化开可点,正是靠"内联 auto 覆盖继承来的 none")。
  第一版默认 auto,于是"霜还没化就能点开碎片"。
· 父层是 none【不代表】子树不可命中:先递归往下看,再决定是不是命中它自己。
· [hidden] 的子树跳过(= display:none)。
```

**这条断言必须能红。** 验证办法(脚本在 `.tmp/`):

```bash
node .tmp/mutate.mjs            # 把"挂到 layer 上"这个 bug 注回模块副本
node .tmp/frost-mutant.test.mjs # 对着变种跑同一套断言 → 应该红
```

**② 配色:按"主题"配,而不是按"它所压的那个面"配。** 第五张盘永远是一扇**夜里的窗**,
跟 `data-theme` 无关 → 这一页**故意没有** `data-theme` 覆写。
(对照:第一张盘 `.self` 的底色跟着屏幕走,所以它**必须**有浅色覆写。
判断依据是"这个颜色压在什么面上",不是"现在是什么主题"。)

**③ 画法本身就是风格 —— "省事"会变成"不搭"。** 第一版每个 `CELL=7` 的格子画一个色块,
用户的原话是**"像素风格的整体美感好不到哪去,也不搭"**。方块是最省事的画法,而这一站的语汇是
细线 / 辉光 / 矢量。现在霜 = 一层薄乳白膜 + 三级尺度的线段(密针 / 羽状小蕨 / 六角枝晶),
而且只在尺寸变了才画一次:每帧只做 `texture → destination-in(覆霜场)` 两次 `drawImage`。
测试里因此钉了三条**画法**断言:主画布上的逐格 `fillRect` 必须接近 0、
`stroke` 必须被调用、`drawImage` 必须是偶数次。

**④ Hugo 注释的收尾是 `*/}}`,一个字符都不能差 —— 这个坑踩了四次。**
于是写成脚本,不再靠眼睛看:

```bash
node .tmp/scan-comments.mjs tuagfey-blog/layouts/partials/pages/future.html
```

(写这个脚本时我又踩了一次:脚本自己的开头注释里原样写了那三个字符,
把 JS 的块注释提前关掉了。同一种错的第四次。)

**⑤ CSS 的 `[hidden]` 会被自己的 `display` 盖掉。** `.frost-read` 写了 `display: grid`,
于是"关掉"的读数层照样铺在屏幕上、还挡住点击。必须补一条
`.frost-read[hidden] { display: none }`。站里第一张盘也踩过同一个坑(`.self-card[hidden]`)。

**⑥ ★ 帧驱动写错,会让"功能明明是对的"看起来是坏的。**
这个模块的循环是 `rAF → setTimeout(TICK=40ms) → rAF → …`。
验收脚本里的 `frames(n)` 原来是"等 2ms 就跑一次 rAF 队列" ——
2ms 之内那个 40ms 的定时器根本没响,队列是空的:**一帧都没跑**,断言读到的是旧值。

症状是"焦点化霜"那条一直红,而它其实**打对了地方**:
`api.covAt(316,378)` 明明是 0,`diag` 里那一片却还是 1 ——
因为 diag 是上一帧的快照,而"下一帧"从来没发生。我在这上面绕了好几轮,
一路怀疑坐标、怀疑闭包、怀疑 zone 映射,就是没怀疑"帧根本没动"。

现在 `frames()` **每帧等 55ms(> TICK)**,并在注释里写明原因。
教训有两层:**① 循环是异步链的时候,"跑一帧"必须等它那一环;**
**② 又验证了那句老话 —— 数字反直觉时先怀疑量具。**
为了以后能立刻定位这类问题,模块现在暴露了两个诊断入口:

```js
api.covAt(x, y)      // 这个 CSS 坐标上的覆霜量是多少(定位"暖化打偏了")
api.state().lastMelt // 最后一次暖化打在哪、力度多少
```

**⑦ 一条"能用"的路,可能差一点点就是假的。** 键盘用户 Tab 到碎片时会在那一片
"呵一口气"(focus → 局部化霜)。第一版只呵一口,整片平均覆霜量只降到 0.6 左右
(`--clear ≈ 0.47`),**差 0.03 到不了"可点"的阈值** —— 也就是说键盘用户 Tab 过来
却打不开,这条路等于不存在。现在沿碎片长轴呵三口气(`--clear ≈ 0.58`)。
教训:**给"可达性"写的代码,必须验到"真的能走完",不是"看起来接上了"。**

**⑧ 触摸和鼠标不是一回事。** `onUp` 原来只清 `pressing`,不清 `warm.on` ——
手指抬起之后,霜在那个点继续化、水滴一直往下掉(鼠标悬停当然应该继续暖,
所以这个 bug 只在触摸下出现)。现在松手即停,并且有一条专门的断言钉住它。

**⑧ ★ 浏览器合成的 click,目标是【按下与抬起的最近公共祖先】——
而 `setPointerCapture` 会悄悄改写它。** 用户报"碎片点不动",而 55 条断言全绿。
原因:模块在 `pointerdown` 里就调用了 `setPointerCapture`,
于是 `pointerup` 被重定向到 `.frost`,click 就落在 `.frost` 上,碎片永远收不到。
测试没抓到,因为它**直接给碎片 `dispatch('click')`**,把这一整条链绕过去了。

现在测试会**合成 click**:记下 pointerdown 的目标,pointerup 时在"按下目标与抬起目标的
最近公共祖先"上派发 —— 和浏览器一致。修法是:**只在真的拖起来之后才捕获**
(轻点 → 不捕获 → 碎片拿到 click;拖起来 → 捕获 → 划出窗也能继续化霜),
另外"按住期间走过超过 6px 就当拖",免得划过一片碎片时顺手把它打开。

**⑨ 1~8 像素这个尺度上,方框的四个角会露出来。** 雪和星星原来都是"方框套方框"
(光晕一个方块 + 芯一个方块),自检放大图里看得清清楚楚:一片雪就是**带边框的小方块**,
一颗星就是**小方片** —— 用户说的"雪花跟流星一样 / 背景星空不好看",根子在这儿
(不是大小、也不是速度的问题)。现在统一用 `softDot`:一个核 + 一个"十"字光晕,
十比方的角少得多,缩到 3 像素看起来就是圆的。
**放大自检图是唯一能看见这种事的手段** —— 1:1 的时候它们只是"有点脏"。

**⑩ 量具要跟着"画布被清空"一起清空。** 假 canvas 把每一笔 `fillRect` 记在
`calls.rects` 里(`clearRect` 时清空)。可 `sizeCanvas` 是直接改 `canvas.width` ——
浏览器里那等于**清空画布**,而记账没清,于是 resize 几次之后,
`calls.rects` 里混着**以前那几个尺寸**画的内容:测试报出"天上有 135 颗背景星",
其实是 375 宽那一次画的天。现在假的 `El` 也实现了 `width/height` 的 setter,
赋值时清账。**"清空"这件事,量具和被测对象必须理解成同一件事。**

**⑪ 判据要用"哪个更多/更少",别用绝对阈值。** "屏幕缩放后光标不偏"那条,
第一版写成"视觉坐标那个点必须还是 1" —— 结果它读到 0.91:测试前面几轮留下的
水滴还在往下掉,沿途化出了细细的水痕,任何"必须等于某值"的断言都可能被它们踩到。
改成"内部中心明显比视觉那点更化得开"(修好之前是反过来的)之后,
既准确又不会被无关的动画干扰。
**后来发现它还有一个更严重的问题:整条断言是空跑的**(见 ⑬)。

**⑫ ★ 同一块画布的「CSS 盒子」和「后备缓冲」必须分开写。**
`sizeCanvas(cv, W*dpr, H*dpr)` 把同一个数同时写进了 `canvas.width` 和
`canvas.style.width` —— 在 dpr=2 的屏幕上,霜那张画布会变成面板的**两倍大**
(只露出左上四分之一),而且一格从 7px 变成 14px,可 `measureZones` / `melt` /
`covAt` 全都按"一格 7 CSS px"算。症状正好是用户报的那半句:
**"霜在光标底下化了,可底下那片字不亮、点不动"** —— 化的地方对,亮的地方错。
现在 `sizeCanvas(c, wCss, hCss)` 只接收 CSS 尺寸,后备缓冲自己乘 dpr;
sky / aurora / snow 三张画布的作图坐标也一并改成设备像素。

**这个错在 dpr=1 的测试里永远看不见**,所以测试里专门加了一段
"把 shim 的 `devicePixelRatio` 改成 2 再重建":验画布的 CSS 盒子 == 面板尺寸、
后备缓冲 == 2 倍、**光标压在某一篇碎片上划十几下那一片必须亮起来**、
以及雪花要铺满整块画布(旧代码会让它们全挤在左上四分之一)。

**⑬ 量具的"注入"没生效,断言就是空跑的 —— 而且它会绿。**
"屏幕被缩放时光标不偏"那条原本用 `cv._rect = 1600×960` 来仿真"屏幕放大 1.6 倍",
可假 DOM 的 `getBoundingClientRect` **优先读 `style.width`**,而 `sizeCanvas` 每次都写它 ——
所以 `_rect` 在 canvas 上根本不生效,仿真压根没发生;更巧的是断言当时用的
"哪个更化得开"恰好被前面留下来的水滴满足,于是**它一直绿着**。
现在假 DOM 多了一个 `_forceRect`(强行指定 rect,专门用于仿真),
断言也改成在**干净状态下读绝对值**(内部中心 0 / 视觉那点 1)。
**这条是被子代理一眼看出来的**(它按同语义的假 DOM 实测:`_rect=1600` 之后 `rect.width` 还是 1000)。

**⑭ 用户说"位置不对"时,先问清楚"他看到的是哪个光标"。**
排查者把祖先链、dpr、pointer capture、z-index 全排掉之后,注意到站里
`magnetic-cursor.js` 的磁吸选择器里有一个裸的 `"button"` —— 而**碎片就是 `<button>`**:
鼠标悬上去时,画出来的那个十字光标会被磁吸到碎片中心、同时把中心点藏起来
(`MAGNET=0.12`),**真的指针还在原地继续化霜** → 看上去就是"光标和化霜的位置对不上"。
已在选择器里排除 `.frost-shard`。教训:定位到"某个坐标算错了"之前,
先确认偏差是**发生在计算里,还是发生在用户看到的那一层**。

**⑮ ★ 同一个路径的图,第二次读到的可能是【第一次那一版】。**
这一轮我两次读 `.tmp/dbg-onlysky.png`,拿到的 sha 完全一样 —— 而那个文件在两次之间
**确实被重写过**(天空从"亮雪地"改成了"黑剪影")。也就是说:渲染完直接按原路径读,
看到的可能是旧图,**而我会照着旧图下结论**。
现在自检脚本的规矩是:**每次渲染完,把图复制成一个新文件名再看**
(`v5-aurora.png` 这种)。这条比它看起来严重 —— 视觉判断是这个项目里唯一
"没有别的东西能交叉验证"的环节。

**⑯ 启发式会随着设计一起过期,而且过期之后会【报假警】。**
自检脚本里原来有一条:"地面比天上亮 8 以上,否则就是 canvas 没画地面" ——
那是"雪地"版本写的。用户改成"黑色剪影"之后,地面**本来就该比天上暗**,
于是它开始喊"★ 差太小 —— canvas 还没画地面",而地面画得好好的。
现在改成正反两面判(既要和天上明显不同、又要接近黑),并且把"山脊上那道冷光在不在"
单独列一条 —— **判据要写成"设计意图",不能写成"上次那个数"**。

**⑰ "假极光"的判别特征(这一轮的收获)。** 极光重写过两次,两次都是
**自检图上先看出问题**:第一版是"横向色带 + 上缘最亮"(像视频信号不良),
第二版噪声版画完还剩一条**笔直的水平切线**——那是因为裙边下方用了硬 `continue` 截断。
真实的极光是竖直的帘子:帘边被低频噪声推弯、细射线用高频噪声、
**裙边最亮且上下都要软**、颜色按高度从绿(557.7nm)过渡到青/紫。
做法上最有用的一条:**在小分辨率离屏画布上逐像素算噪声场,再 `drawImage` 平滑放大** ——
和霜的覆霜场同一套办法,所以既没有格子、也不需要模糊。

**⑱ 极光的量化判据,以及"判据方向搞反"这一坑。**
极光重写的第三版用了子代理从网上查证后给的骨架(见 `aurora-research.md`,那是
662 行的调研报告:真实极光的结构事实 + 4 份真源码 + 一张"假极光"速查表),
并把它那三个指标做进了自检脚本:

```
gradRatio  = mean|∂A/∂y| ÷ mean|∂A/∂x|   健康 0.30~0.60;横带 >1(对照组 9.82);栅栏 <0.15
coverage   = 被点亮像素的比例             健康 0.40~0.66(>0.6 是"均匀发光板")
brightFrac = A>0.35 占被点亮像素的比例     健康 0.10~0.18(>0.25 是"发光果冻")
```

**我把 gradRatio 写成了 x/y(方向反了)**,于是健康的 0.59 被读成 1.69、
屏幕上打出一个"✗ 偏横带" —— 差一点就去"修"一个本来完全正确的极光。
分子分母的方向是有物理含义的(帘子沿 y 平滑、沿 x 有细节 ⇒ 纵向梯度【小】),
不是随便约掉的。**这和"读图读到旧图"是同一类错:量具先错,后面所有结论都跟着错。**
所以现在这条会把【高通口径】和【未高通口径】两个数一起打出来,不给"只有一个数、
看着不对就调参数"的机会。

**⑲ 判据要连"设计意图"一起写下来。** 自检脚本里原来有一条"地面要比天上亮 8 以上,
否则就是 canvas 没画地面" —— 那是"雪地"版本写的。用户改成"黑色剪影"之后,
地面**本来就该比天上暗**,于是它开始喊假警。现在改成正反两面判(既要和天上明显不同、
又要接近黑),并把"山脊上那道冷光在不在"单独列一条。
**阈值可以改,但"为什么是这个阈值"必须写在旁边。**

## ★★★ 最危险的一次:测试绿,而那段代码从来没跑过

用户的第三轮反馈里有一句:"捡起碎片的动画一点都没做,也就是说你这一轮啥也没干。"
他说得对。`openShard` 里明明写着飞行逻辑,但那个分支**一次都没进去过**:

```js
if (readEl) { readEl.hidden = false; readEl.classList.add("is-on"); }
...
var mb = readMark.getBoundingClientRect();   // ← 全是 0
if (b.width > 0 && mb.width > 0) { ...飞... }  // ← 恒为假
```

浏览器在**同一帧内**刚把元素从 `display:none` 改回可见时,布局还没重算,
`getBoundingClientRect()` 返回 `{0,0,0,0}`。而我的假 DOM 返回的是 `_rect` 的默认值
(1000×600),**从来不返回 0** —— 量具把一个"永远走不进去的分支"照成了"走通了"。

**这类错比"测试红"危险得多**:红会逼我去查,绿只会让我以为做完了,
然后我还写了一大段"我修好了什么"去汇报。用户连着两轮说"还是没有动画",
我两轮都以为是他没看到。

**修法有两条,两条都做了:**

1. **模块侧**:不再 measure 那个可能还没布局的元素。面板是 W×H、卡片是居中的、
   槽是卡片内固定 96px 的一项 —— 这些都**算得出来**,而且不受"这一帧布局算没算"影响。
   (代价:卡片尺寸公式在 CSS 和 JS 各有一份,两边都写了注释指回对方。)
2. **量具侧**:假 DOM 的 `hidden` 现在有 setter 同步一个 `_isHidden`,
   `getBoundingClientRect` 会**沿着 parentNode 往上找**,只要有祖先 hidden 就返回全 0 ——
   和浏览器一致。这一类 bug 从此拦得住。

**规矩:凡是"刚改了可见性就读几何"的代码,都必须能被一个返回 0 的量具验出来。**
我用这条新量具复跑了全部断言 —— 动画那几条仍然通过,说明修法是对的。

**结论:报出反直觉的数字时,先怀疑工具,再怀疑被测对象。**
所以现在这些脚本里有几条"元断言":
"取到了星星坐标(取样逻辑没坏)"、"模块给出了每句话的格子区(diag 可用)"、
"抠出来的部件不能有空坐标" —— **工具本身也要有自检**。

## ★★ 一次真的写坏了文件:改代码的脚本必须只认结构

改星座那一段时,我写了个 Node 脚本做"整段替换"。它要找起点,用了四个模糊片段
(`'每片碎片对应的那颗星'`、`'★ 0.80'`……)去 `findIndex`,再**往回走**找注释开头。
结果第一个命中的片段落在**第 88 行**一句 globals 注释里:

```
var starAt = [];   /* 每片碎片对应的那颗星:{x,y}(0..1 比例)*/
```

往回走一直走到文件第一行的 `/*` 才停 —— 于是脚本"整段替换"了**前 744 行**,
1300 行的模块只剩 705 行。

**而且没有 git 兜底:`assets/js/page-frost.js` 是未跟踪文件(`git status` 显示 `??`),
`git checkout` 救不回来。** 最后是从 `public/js/` 里那份 Hugo 指纹产物(上一次
`hugo` 构建留下的、内容完全一样的副本)恢复的。**那次构建救了这一整页。**

从那以后,改这个文件的规矩是:

1. **匹配只认结构,不认散文。** 起点认 `startsWith('var ANCHOR = [')`、认函数名,
   绝不认注释里的字 —— 注释是给人看的,它随时会飘到别处/被改掉。
2. **一次只改一个点**,改完立刻 `node --check`。四处一起改,出错时分不清是哪一处。
3. **范围要有合理性断言**:`if (to - from < 20 || to - from > 200) throw` ——
   真出事的那一次,范围是 744 行,一眼就不对。
4. **先 `--dry` 打印出边界前后各一行**,确认之后再写。
5. **被替换掉的原文另存一份**(`.tmp/constellation-black*.js`)。写坏的那一刻,
   我手里唯一的原文就是这份黑匣子。
6. **不要用 PowerShell 的 `Get-Content` / `Set-Content` 改这些文件** ——
   Windows PowerShell 5.1 不是 UTF-8,中文注释来回一趟就变成乱码(这条踩过两次)。
   用 `write`/`edit` 工具,或 Node 的 `fs`。
