# 第三张盘「迷茫」— 接手指南

> 这份文档是给"下一个会话/下一个接手的人"看的。当前进度、怎么跑、还差什么、悬而未决的决定,都在这里。
> 最后更新:第 15 轮(里程碑 11/12 达标)。

## 1. 这是什么

第三张盘从"从零手搓的几何冲刺小游戏"改成了**新引擎**:

- **玩法**:复刻几何冲刺的骨架 —— 跑、跳(长按连跳)、形态(方块 / 飞机)、尖刺与方块侧面致死、
  平台与地面单向接住、坑掉落致死、圆环切形态、速度门、重力门、存档点、终点进度;
- **视觉**:本站的显示器 + holo 科技风,**不使用任何 RobTop 美术**(那是版权物);
- **关卡**:按段落与形态**自动铺面**生成,不追求采音(原作本身也没有严格采音标准);
- **参考**:[OpenGD](https://github.com/Open-GD/OpenGD)(关卡格式与数据结构)、
  [camila314/gdp](https://github.com/camila314/gdp)(GD 物理函数反编译)。

旧的自研实现在 **tag `lost-from-scratch`** 里归档(含那份 `draft()` 自动铺面算法)。

## 2. 代码在哪、怎么跑

```
tuagfey-blog/gd-web/            ← 引擎源码(独立 npm 工程,Hugo 不碰它)
  src/sim/                     ← 纯 TypeScript 定点模拟核心【零依赖、零引擎】
    constants.ts               ← 物理常量表(全游戏唯一的"手感数字",每条标了出处)
    level.ts                   ← 关卡模型 + 按段落/形态的自动铺面生成器
    world.ts                   ← 定点模拟 + 机器人(botThink)
    replay.ts                  ← 回放 + 状态指纹
  src/render/  ← 无(渲染直接写在 main.ts 里,见下)
  src/main.ts                  ← Phaser 4 场景:固定步长驱动 sim、相机、科技风绘制、音乐、HUD
  src/embed.ts                 ← 页面入口:找 #gd-canvas 启动;手机端不启动
  test/sim.test.ts             ← 14 条 Node 验收
  tools/                       ← 一次性补丁脚本与排查工具(diag-bot.ts 很好用)
  vite.config.ts               ← 预览页构建(输出 dist/)
  vite.lib.config.ts           ← 博客用单文件构建(直接写进 static/assets/gd/gd.js)

命令(都在 gd-web/ 下):
  node --test test/sim.test.ts   # 模拟核心验收(14 条,零依赖)
  npm run build:embed            # 构建给博客的 gd.js(约 387 KB gzip)
  npm run build                  # 构建预览页 dist/
  node tools/diag-bot.ts         # 排查"机器人在哪儿死的"逐帧轨迹
```

验收脚本在 `tools/verify/`(仓库上层):

| 脚本 | 验什么 |
|---|---|
| `gd-web-check.mjs` | 预览页:画布、起跑闸门、音乐、机器人跑完整关、**浏览器与 Node 逐帧指纹一致**、帧率、首包体积 |
| `gd-panel-check.mjs` | **真实页面 + 显示器框**:引擎起来、画布尺寸、按一下开跑、音乐、HUD 内容、0 报错 |
| `live-lost2.mjs` | 站点整体:开始菜单、BGM 所有权、CD 架暂停等 |

## 3. 架构上的两条硬规矩(别破坏)

1. **`src/sim/` 里不许出现 `phaser` / `window` / `document`** —— 有一条测试专门扫源码盯着。
   好处已经兑现过:换渲染器、改画幅、接音乐、搬进博客、改美术这一路下来,模拟核心的
   **确定性和可通关性一点没动**。
2. **自动生成的关卡必须"机器人 0 死亡可通关"** —— 那条用例是地基。
   任何铺面改动**先跑机器人**;过不去就不许提交(第 9、11 轮各回退过一次,都是这条规矩救的)。

## 5. 还差什么 / 悬而未决

**唯一没验的里程碑条目**:**真机 60fps**。我这边只有无头软件渲染(SwiftShader,52~57 fps),
量不了真 GPU。现在页面左上角 HUD 会直接显示 fps —— 打开看一眼即可。

**三个待用户拍板的决定**(已问多次,未答复):

1. **要不要把这些提交推云端?** 目前本地已攒 **20 个提交未推**(最新 `f5c1cf3`)——
   不只是新引擎,还有更早修好的圆环/斜轨/存档点/编辑器。
2. **难度曲线走哪条**:
   ① 接受现状(平坦、稳定可通关);② 升级机器人(加落点预判/空中二段/形态时机),让它能当更强参照,
   然后才敢把关卡做难;③ 自动铺面只起稿,难处手动摆(需要把关卡编辑器捡回来)。
   已知:`test` 里的机器人**只会看"前方最近障碍的远边"**,所以"组合障碍"(尖刺后 0.5 块叠方块)
   它过不去 —— 代码思路没错(跨度 4.0 块 < 一跳 4.49 块),死因是机器人太笨。
3. **下一步优先**:美术氛围(粒子 / 光晕 / 镜头抖动 / 段落切换提示)还是手感调优(跳跃、速度、形态)?

**已知的小欠账**:

- 关卡只有一种难度档、一条固定种子(`generateLevel({ seed: 20260913 })`),没有关卡选择;
- 存档点 / 圆环 / 速度门的视觉还能再打磨(现在:圆环=双层环+目标形态小图形、存档点=旗子、速度门=双箭头);
- 死亡只是 HUD 变红 + 自动复活,没有专门的死亡菜单(旧版有,新引擎还没做);
- 手机端只是"不启动 + 显示请用 PC 打开",没有独立提示页(用户提过"或者手机端直接去掉主页");
- 音乐是页面层 `<audio>`,没有和 sim 做任何时间对齐(设计如此:GD 不是节奏游戏)。
