### 关于 SPWN

用户提过"甚至可以直接用 SPWN 语言编程生成铺面"。**SPWN 是把关卡编译成 GD 的 `.gmd` 格式的编译器**,
我们的引擎读的是自己的 `Level` 结构,没法直接吃 `.gmd`。所以这一轮做的是**借它的模型**:
铺面写成"按 onset/节拍的事件 + 图案库"(`level.ts` 里的 `patSpike / patSpikeOrb / patPitOrb / patPadRun`),
而不是"每 6 块一个随机障碍"。真要用 SPWN,可行的路子是"离线编译成一段显式物件列表(JSON)→ 引擎读 JSON",
但那样就没有"自动生成"了,得先决定要不要放弃自动生成。

## 1. 这是什么

第三张盘是一个**复刻几何冲刺玩法的网页关卡**:

- **玩法**:跑、跳(长按连跳)、形态(方块 / 飞机)、尖刺与方块致死、平台单向接住、坑、**弹簧**、**空中跳环**、
  圆环切形态、速度门、重力门、存档点、终点进度;
- **视觉**:本站的显示器 + holo 科技风,**不使用任何 RobTop 美术**(那是版权物);
- **关卡**:按**采音 onset 自动铺面**(`data/lost-beats.json` → `src/sim/beats.ts`),全曲 156.76 秒 / 1686 块;
- **时间**:画面由**音乐时间驱动**(`audio.currentTime` → 该推进到第几帧),所以障碍真的踩在鼓点上;
  复活时音乐 seek 到存档点对应的时间,后面每一拍仍然对得上。

参考:[OpenGD](https://github.com/Open-GD/OpenGD)(关卡格式)、
[camila314/gdp](https://github.com/camila314/gdp)(物理函数反编译)、
[GD 2.2081 的在线反编译](https://gd-src.undefined0.dev/)(本轮常量的出处,整理在 `docs/gd-physics-triggers.md`)。

旧的自研实现归档在 **tag `lost-from-scratch`**(含旧版 `draft()` 铺面算法与采音模块 `gd-beat.js`)。

## 3. 架构上的三条硬规矩(别破坏)

1. **`src/sim/` 里不许出现 `phaser` / `window` / `document`** —— 有测试扫源码盯着。
2. **自动生成的关卡必须"机器人 0 死亡可通关"** —— 任何铺面改动**先跑 `node tools/diag-bot.ts`**。
   这一轮它抓出 6 个必死图案,每一个都写进了代码注释(见下)。
3. **改物理常量 = 改铺面**:所有图案几何都是从常量推出来的(`level.ts` 的 `heightAt/arcOf/jumpLead`),
   常量一动,`diag-bot` 与 20 条测试必须重跑。

## 4. 这一轮踩过的坑(都留在注释里了)

1. **落点被"惯性跳"吃掉**:玩家按住不放 = 落地自动连跳。如果下一个障碍正好落在那一跳的落点上 → 必死。
   → `safeEnd()`:下一个"要出手"的障碍,右边缘必须超出"落地后一跳够得到"的距离。
2. **弹簧被提前起跳躲过**:机器人在离弹簧 2 块时看见弹簧弧线里的刺,提前起跳、从弹簧头顶飞过去。
   → ① 弹簧连**第一个弧线里什么都不放**;② 弹簧间距**不许超过一跳的跨距**(中间不留"在地上跑"的空档);
   ③ 弹簧连还要一段**干净的助跑道**(前面有刺就得先把这一段的 onset 让开)。
3. **弹簧"临界距离"算错**:扫"脚底低于 0.625 块"时从 d=0.02 开始,第一次就成立 → 临界值算成 0.02,
   弹簧间距直接乱掉(实测 5.25 块的间距让玩家从弹簧头顶飞过)。要取**下落时穿过** 0.625 块的那一处。
4. **触发点比物件左缘早 0.625 块**:内框右缘先碰到它。所有弧线几何都要按这个偏移算,否则差半块、当场撞死。
5. **机器人会为"已经过去的刺"起跳**:按外框判"过去了"太晚 → 落地瞬间被动起跳。
   → 按内框判:`o.x1 <= w.x + P.innerOff`。
6. **弧线下面放方块 = 断链**:方块把地面抬高 1 块,玩家落在方块顶上之后够不到下一根弹簧。
   → 弹簧弧线下面**只放尖刺**。

3. **提示符只有一个**了(引导打完后把提示符"收"到底部,原来是又新建了一个);
4. 快捷键改成 **Ctrl+Shift+C 中断 / Ctrl+Shift+V 粘贴 / Ctrl+Shift+L 清屏**,
   纯 Ctrl+C / Ctrl+V 一律不拦(要能选中台词复制);
5. 终端**不再顶出模拟屏幕的框**,而且**严丝合缝**:
   · 运行时把外框贴图 `/assets/screen/frame.webp` 读进 canvas(缩到 1/4 算,毫秒级),
     ② 求"完全落在透明区内的最大内接矩形"→ 这是**文字区**(`.term-screen` 的 `--term-inset-*`);
     ③ 再逐行扫出窗口的真实轮廓,拼成多边形 → 玻璃层 `.term.is-fitted` 铺满视口后用
     `clip-path: var(--term-clip)` 裁出屏幕那一块。
   · 为什么两层:外框四角是**斜切**的,只用一个矩形要么顶进斜角(用户报的"顶出边框"),
     要么缩掉一大圈(看着像悬在框里)。玻璃按轮廓裁 + 文字待在内接矩形里,两头都不占。
   · 为什么不用写死的百分比:`frame.webp` 是静态资源、**没有指纹**,浏览器里可能是旧缓存,
     而且宽高比一变斜切角对不上。量不到图才退回 `terminal.css` 里那组保底百分比
     (`tools/verify/frame-window.mjs` 量的:top 8.224% / right 5.455% / bottom 8.553% / left 3.636%)。
   · 排障:控制台敲 `CD4Term.measure()` —— 视口 / 外框窗口 / 文字区 / clip-path /
     导航让位(带"为什么算没露出来")一次全给出来,让用户贴过来即可。
     ★ DevTools 停靠在右侧会把页面挤窄(用户量到 167×813),截图/量数据时先取消停靠。
6. 顶部导航默认是收起的 → 终端**默认不让位**(`--term-gap-top` 默认 0),
   只有导航真露出来(没 `statusbar-hidden`、display/visibility/opacity 都可见)时才量它的高度。
   ★ 两个坑:① 首次量不能在 `initStatusbar()` 之前跑(那时 `statusbar-hidden` 还没加上);
   ② 参照物必须是**文字区** `.term-screen`,不能是 `.term` —— 量到外框后 `.term` 铺满视口、
     `top` 恒为 0,拿它比会让让位量恒等于 0(两轮都踩了)。现在头 10 秒每 450ms 重算一次,
     之后靠 MutationObserver(body 的 class)+ 点收起箭头 + resize 兜。

## 10. 外框贴合 FrameFit(五张盘共用,2026-09 这一轮)

用户先在第四张盘的终端上发现"内容顶出金属外框",随后说"剩下四张CD都有同样的问题" ——
确实有:屏幕上所有东西原来都按 `.screen` 的 `--sp-t/--sp-x/--sp-b`(13vh/5vw/7.5vh)落位,
而那块贴图(2200×1216,按 100% 100% 拉伸铺满视口)中间的透明窗口才是可视区。

**量窗口的坑(两轮才量准)**:
- 别用"中线上一整段透明":贴图左缘中段有个**电源键凸起**,会把左边界从 77px 带成 52px;
  四角的斜切也会污染上下边。1440×900 下真正可用的窗口约 **79,98,1359,811**。
- 现在:左右边界取**逐行轮廓的中位数**(只统计宽度超过半屏的行,凸起/切角算离群值),
  上下取中线透明段的两端;另外求"最大内接矩形"给内容当兜底。

`assets/js/frame-fit.js`(新,五张盘共用)在运行时:
1. 把 `/assets/screen/frame.webp` 读进 canvas(缩到 1/4 算,毫秒级);
2. 逐行扫出**窗口轮廓**拼成多边形 → `--ff-clip`(给"玻璃"裁边用,斜切角严丝合缝);
3. 输出窗口四边 `--ff-win-*` 与"窗口再收 14px"的 `--ff-safe-*`(给内容用);
4. 加 `html.frame-fitted`,并把 `.screen` 上那套 `--sp-*` **直接落到窗口四边 + 4px**
   (不再取 max —— 第二张/第三张那种自带整块暗色底的页面,原来四周留着一圈站点底色,
   看着像"浮在框里的小方块";现在它们正好铺到金属框内缘);
5. resize 时重算并派发 `frame-fit`;`FrameFit.ready(cb)` / `.debug()` 给别的模块和排障用。

接上的地方:
- **五张盘的开机动画**:`html.frame-fitted .screen-static` 铺满视口 + `clip-path(--ff-clip)`,
  里面画动画的 canvas 收到 `--ff-safe-*` 里。五套动画都是按 canvas 的 W/H 百分比画的,
  **盒子一收内容自然进安全区,一行渲染代码都没改**;花屏(`.is-full`)时 canvas 放回全屏。
  ★ canvas 是替换元素:`width:auto` 会退回 300×150,必须用 `calc(100% - …)` 算宽高(踩过)。
- **第四张盘的终端**:`cd4-terminal.js` 自己的那套测量删掉了,改成 `FrameFit.ready()` 取数
  (玻璃 `--term-clip`、文字区 `--term-inset-*`)。★ FrameFit 给的 `win/safe` 是**图上坐标**,
  换算时右边的写法是"坐标 − gap",不是"视口宽 − 坐标"(混过一次,终端被压成 0 宽)。
- **页面内容**:滑动分页 / 行星模拟 / 游戏 / 留白面板都吃 `--sp-*`,跟着落进窗口;
  第二张(行星模拟)和第三张(游戏)自带整块暗色底,是这次最主要的受益者。
